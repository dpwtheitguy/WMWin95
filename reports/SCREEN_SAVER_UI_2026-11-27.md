## Functional design

`apps/screensaver_host.py` serializes preparation and owned runtime operations on workers. GTK never runs Wine prefix initialization, child wait, bounded stop or idle scheduler stop. Generation checks prevent an old preparation request launching after selection changes, cancellation or destruction. A waiting full-screen child does not hold the worker serialization lock, so cancellation can actually stop it. Separate runtime instances share per-presentation prefix storage and a runtime lease, preserving native Settings values for later idle activation while keeping ownership distinct.

Session idle uses measured XScreenSaverQueryInfo server time. A running xfce4-screensaver owner inhibits the new scheduler; selected Apply reports a native explanation rather than competing with an existing owner. No daemon is killed and no lock policy or elevation flow changes. Full-screen Preview and Settings remain usable separately. Until an existing-session-daemon adapter or explicit ownership transfer is implemented, automatic activation in such a session is **not accepted**.

Settings currently launches the original `/c` UI. Independent runtime testing confirms actual native configuration changes for tested controls, but Wine typography is not pixel-accepted. Embedded monitor `/p HWND` is not enabled; a GTK XID cannot substitute for a Win32 HWND. The native monitor remains illustrative until the owned Win32 preview host is packaged and qualified. Password protection and monitor-power controls explain that those settings belong to session locking/Power Properties.
