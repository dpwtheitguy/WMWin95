# Fonts Control Panel folder — November 26, 2026

Fonts is implemented as a native-style Explorer folder window, not a property sheet. It reads actual Fontconfig inventory, previews the selected file, and installs/removes managed personal fonts with cache updates. The full Windows 95 Fonts feature set and every visual state are not accepted yet.

## Native reference and reusable assets

Original captures are in `private/screenshots/fonts-20261126/`: classic Fonts folder, empty/selected File menu, Edit/View menus, selected Arial, actual Font Viewer and Add Fonts dialog. The original folder measures **600×411 pixels at (66,66)**; its icon cells are 75 pixels, with the first TrueType canvas at **(27,46)**. Font Viewer measures **371×414 at (215,79)**. The classic VM was checkpointed before inspection (`before-fonts-reference-20261126`) and after capture (`fonts-reference-captured-20261126`); both checkpoint creations were verified. No original fonts were installed or removed. The native Fonts folder remains visible for comparison.

`tools/stage_fonts_assets.py` stages the reviewed frames, original FONText folder/TrueType/bitmap/OpenType icons at 16/32 pixels, and private original font files used for preview/testing. It returns provenance records, including every frame region cleared of dynamic content. Original binaries and screenshots remain private.

## Working behavior

- Actual installed font families, styles, formats, files and face indexes come from Fontconfig. Windows bitmap FON collections are grouped by file in the large-icon view. The implementation supports large icons, a basic list/details view, selection/range/inversion, type-to-select, keyboard endpoints/page movement, refresh and status-bar toggling.
- Preview reads bounded SFNT name-table metadata and renders real glyph samples at multiple point sizes. Each preview has its **own Pango/Fontconfig map containing the selected file**, so another installed font with the same family/style cannot silently substitute for it. This does not change the application's global font configuration. Missing-glyph fallback is disabled for the samples. Actual legacy/symbol/collection rasterization still requires broader reference acceptance.
- Install New Font uses the existing shared native-style Open file dialog. Source validation uses FreeType/Fontconfig; invalid data and unsupported formats are rejected. The file is copied into `~/.local/share/fonts/Win95LX`, the real font cache is updated, visibility is verified, and ownership/hash records are saved atomically. Cache/record failures roll back the new file.
- Delete requires confirmation and only removes unchanged files installed by this tool inside its personal directory. System fonts, untracked personal fonts, symlinks, externally changed files and files outside that directory remain read-only with reasons. Failed removal restores the original file and record. If another file appears at the original path during rollback, it is preserved and the recovery copy is retained with a clear error.
- Source/destination collisions never overwrite existing files. Concurrent replacement during a failed install is preserved. Nested source folders can be enumerated; the current install dialog selects individual files.
- Caption drag, resize, maximize/restore, minimize, caption-icon system menu, Alt+Space and canceled keyboard Move/Size use the shared system-menu command profiles. Native popup menus support pointer/keyboard selection and disabled-state reasons through Help.
- Clipboard support currently accepts local file URIs as text and external GTK URI-list drops. The custom shell's separate file-clipboard/drag implementation still needs explicit interoperation; this is not accepted as complete shell-to-Fonts transfer support.

## Defects discovered and corrected

- The native Fonts focus rectangle is solid, rather than the assumed dotted general-shell style. Its selected outline is yellow (the XOR counterpart of navy), and the blue fill/text origins differ by one pixel. Initial cell comparisons showed 114/126 differing pixels. Measured origins, padding, fill and outline now yield zero differences for both full cell states.
- Font-list Space selection intercepted Alt+Space, preventing the system menu. Modifier dispatch now preserves system-menu access.
- Restoring focus with asynchronous `present()` could race immediate popup reopening. Font-menu dismissal now restores input focus directly to its owner.
- Using the global font map could preview another file with the same family/style and leak application-font additions into subsequent previews. Each preview now uses a private map.
- Recognition alone did not prove a copied font was enabled by the active font configuration. Installation now verifies visibility and rolls back with a reason when configuration rejects it; some legacy bitmap formats can be affected.
- Install/removal rollback could overwrite or delete a concurrently replaced path. Inode checks and exclusive restoration now preserve the newer file and retain recovery data.

## Native cache and per-owned-file bitmap follow-up

The current backend uses `FcDirCacheRescan`, unloads the cache handle, refreshes Fontconfig and checks the actual installed file. The private bitmap policy accepts **exact owned filenames**, not families or wildcard directories. A new fresh-process test establishes a bitmap-rejection baseline, copies an external MS Sans Serif FON into an unmanaged directory, then installs the same family as an owned font. The owned file is independently visible in `fc-list`; the external file remains rejected and byte-identical. Injected install and removal cache failures restore the previous policy, ledger and original font. Final removal keeps the external bitmap rejected. These tests use disposable HOME/config/cache and do not modify desktop fonts. The direct-script unittest entry point was also moved after all test classes so direct execution runs all 23 tests, matching discovery.

A same-host, fresh-HOME operation benchmark is preserved at `private/screenshots/fonts-fast-20261126/cache-comparison/report.json`:

| Operation | Install | Remove |
| --- | ---: | ---: |
| Arial, command-line cache | 2044.916 ms | 2021.689 ms |
| Arial, native cache | 33.986 ms | 11.654 ms |
| MS Sans Serif FON (six faces), native cache | 35.773 ms | 14.308 ms |

Each benchmark performs independent cross-process `fc-list` visibility/removal checks. These are one-operation measurements, not statistical latency guarantees or boot improvements. No source changes to `font_catalog.py` were needed during this follow-up.

Final host GUI evidence is under `private/screenshots/fonts-fast-20261126/800-accepted/` and `1280-accepted/`. Both runs use disposable HOME/config/data/cache and explicitly force `GDK_BACKEND=x11` while removing `WAYLAND_DISPLAY`. `--require-x11` checks the actual GDK backend and requested DISPLAY before creating any window; the report records both, plus exact 800×600 / 1280×800 display dimensions. All functional checks pass and the five named native-region comparisons each have zero differing pixels. Current GUI install/cache/readback takes **55.757 ms** at 800×600 and **36.173 ms** at 1280×800; these are single-operation test values, not input-latency guarantees. The resized window and real Arial preview were inspected; these are not whole-window pixel acceptance claims.

The harness now maps the second Fonts window before exercising file operations and resize, and lets preview-close/focus events settle before opening the next popup. Preliminary runs incorrectly inherited the host Wayland backend despite `xvfb-run`; they are **rejected evidence**, preserved under other `fonts-fast-20261126` subdirectories. All those processes exited and their windows were destroyed; config/font writes remained disposable. The explicit backend guard prevents repeating that test-environment mistake. An extracted test-only twm binary was tried while diagnosing the issue, but final accepted X11 runs require no window manager and install no host packages.
