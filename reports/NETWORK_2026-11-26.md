## Implemented, pending integration

- Pure service-owned NetworkManager configuration model with IPv4 address, contiguous mask, DHCP/manual mode, gateway, DNS/search domains and DHCP hostname validation.
- Original unrelated IPv6, passwords, routes, additional addresses and routing-only DNS domains are preserved. Only explicitly changed supported properties are sent to `nmcli`; human-readable route syntax is not written back.
- Guest-only mutation guard, bounded noninteractive commands, policy preflight rejecting `auth`, optimistic conflict detection, activation and reverse rollback on failure. No terminal or password prompt.
- Authoritative service reread after Apply; failed verification triggers rollback, with incomplete rollback reported honestly.
- Unregistered native-sized Network/TCP-IP property-sheet prototype, segmented IPv4 editor, pending child edits, parent Cancel, asynchronous parent OK, manual DNS server/search lists and gateway editing.

## Not implemented or accepted

- Actual nonadmin service policy is **not installed or accepted**. Follow-up owned-dummy real service transactions passed under maintenance root, including cleanup and unchanged primary networking; real `win95` denial was verified. Root execution is not normal-account UI acceptance. No mutation of the active `ens2` connection or developer SSH route is allowed for testing.
- Main Network adapter inventory rendering, dynamic controls, text, focus, IP glyphs and enabled DNS states are not pixel accepted. Captured frame regions alone do not establish complete visual fidelity.
- Separate primary DNS suffix editing is unfinished; search-domain editing is provided. Ordered multiple gateways and native dead-gateway fallback are unfinished. Existing additional addresses/routes are preserved rather than exposed as misleading incomplete controls.
- Adding/removing connection profiles is unfinished and disabled with an explanation.
- Actual computer-name changes remain gated until the shared stable guest-identity runtime is deployed and tested. Reading the actual current name works. No fake hostname/workgroup preferences are saved.
- Sharing/workgroup/description, client bindings, WINS and NetBIOS require service integration. The guest currently lacks Samba tools; these controls are unavailable with concrete explanations rather than fake Windows drivers or successful no-op controls.
- Advanced/default-protocol selection is unfinished. Windows NDIS/DRV installers are not executed on Linux.
- No native user-facing route, catalog registration or guest policy installation was added; the applet must remain unavailable until integration checks pass.
