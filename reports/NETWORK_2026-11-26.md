# Network applet — 26 November 2026

Status: **development only, not registered or accepted**. No user-visible Linux session, hostname, primary network connection, or guest privilege policy was changed by this work. Windows 98 reference preparation is documented separately.

## Original reference evidence

The offline Windows 95 OSR2.5/IE4 reference was checkpointed as `before-network-reference-20261126`. Temporary pending Client for Microsoft Networks, Dial-Up Adapter and TCP/IP additions exposed the native property pages. No physical adapter or external network was added and the main Network dialog was not committed. The exact checkpoint was deliberately restored after capture; the original empty floppy state was retained.

Reviewed private captures are `private/screenshots/network-native-reviewed-20261126/network-{configuration,identification,access}.png` and `tcpip-measured-page-{0..6}.png`. Original metadata is preserved under `private/reference-tools/network-native-metadata-v2/`. Earlier mislabeled Configuration-only frames and failed tab-switch probes remain preserved but are not accepted as other pages.

Measured Network window: 366×460, OK and Cancel only. TCP/IP Properties: 356×437, page rectangle (13,69,330,325), seven native Win16 pages with rotating two-row tabs. The IPAddress control has four child Edit fields; IP field rectangle (141,232,135,21), mask (141,267,135,21), 33-pixel field spacing. Native IP digits use a distinct 16-pixel, weight-700 font, unlike the general 13-pixel MS Sans Serif UI. This glyph difference remains unresolved and explicitly prevents dynamic IP field pixel acceptance. Automatic subnet-mask inference was not observed; the mask remained blank after entering an address.

The native DNS page clips the bottom search-list region at its page boundary; hit testing must respect that clipping. Disable DNS means DHCP-supplied DNS remains available; Enable DNS overrides DHCP DNS even when no manual servers are entered. The backend maps that exact distinction to NetworkManager `ipv4.ignore-auto-dns`.

`tools/stage_network_assets.py` stages ten reviewed frames with source hashes and parses 28 native NETDI.DLL/MSTCP.DLL Win16 dialog templates. The parser bounds all reads and does not incorrectly align Win16 records as Win32 templates.

## Implemented, pending integration

- Pure service-owned NetworkManager configuration model with IPv4 address, contiguous mask, DHCP/manual mode, gateway, DNS/search domains and DHCP hostname validation.
- Original unrelated IPv6, passwords, routes, additional addresses and routing-only DNS domains are preserved. Only explicitly changed supported properties are sent to `nmcli`; human-readable route syntax is not written back.
- Guest-only mutation guard, bounded noninteractive commands, policy preflight rejecting `auth`, optimistic conflict detection, activation and reverse rollback on failure. No terminal or password prompt.
- Authoritative service reread after Apply; failed verification triggers rollback, with incomplete rollback reported honestly.
- Unregistered native-sized Network/TCP-IP property-sheet prototype, segmented IPv4 editor, pending child edits, parent Cancel, asynchronous parent OK, manual DNS server/search lists and gateway editing.

## Not implemented or accepted

- Actual nonadmin service policy and owned isolated-adapter effects have **not** been tested. No mutation of the active `ens2` connection or developer SSH route is allowed for testing.
- Main Network adapter inventory rendering, dynamic controls, text, focus, IP glyphs and enabled DNS states are not pixel accepted. Captured frame regions alone do not establish complete visual fidelity.
- Separate primary DNS suffix editing is unfinished; search-domain editing is provided. Ordered multiple gateways and native dead-gateway fallback are unfinished. Existing additional addresses/routes are preserved rather than exposed as misleading incomplete controls.
- Adding/removing connection profiles is unfinished and disabled with an explanation.
- Actual computer-name changes remain gated until the shared stable guest-identity runtime is deployed and tested. Reading the actual current name works. No fake hostname/workgroup preferences are saved.
- Sharing/workgroup/description, client bindings, WINS and NetBIOS require service integration. The guest currently lacks Samba tools; these controls are unavailable with concrete explanations rather than fake Windows drivers or successful no-op controls.
- Advanced/default-protocol selection is unfinished. Windows NDIS/DRV installers are not executed on Linux.
- No native user-facing route, catalog registration or guest policy installation was added; the applet must remain unavailable until integration checks pass.

## Tests and required next checks

`python3 -m unittest discover -s tests -p test_network_preferences.py`: **25 passing**, no failures. Cases cover mask/address boundaries, static-to-DHCP clearing, DHCP DNS semantics, preserved extra addresses/routes, escaped names, unchanged field writes, inactive connections, permission denial with no prompt/mutation, activation rollback, rollback failure, external changes, guest guard, gated identity, atomic segmented input, octet navigation, bounded truncated template parsing, and failed post-Apply verification/rollback.

`dev/check_network.py` passed on isolated Xvfb displays at **800×600 and 1280×800**, with separate HOME/config/data/cache. Final artifacts are `private/screenshots/network-linux-20261126/captures-final-{800,1280}/`. Every run captures all main/TCP-IP pages plus configured IP and DNS states. The UAT exercises typed octets, grouped Tab traversal, invalid clipboard paste rejection, gateway and DNS/search additions, child OK pending-only state, parent Cancel with no service call, and asynchronous parent OK with exactly one fake-service apply. Each report includes source/test/asset hashes and actual display dimensions.

Caption/tab and bottom-button regions have **zero differing pixels** at both resolutions. This is a narrowly named region check, not whole-dialog acceptance. Fake-service main-sheet opening took **160.381 ms** at 800×600 and **159.238 ms** at 1280×800; these are warm test-process measurements, not real NetworkManager startup or OS performance claims. Three additional `nmcli --offline connection add` validation cases generated valid keyfiles for DHCP, static IP/gateway/DNS/search, and manual empty DNS without creating profiles or changing networking.

The visual defect pass discovered and corrected radio repaint rectangles erasing native group borders, enabled DNS captions retaining disabled colors, a disabled logon dropdown still appearing enabled, child help incorrectly referring to an absent Apply button, per-octet Tab traversal instead of a whole IPAddress control, and missing invalid-paste feedback. Actual service mutation, rollback under real activation failures, local nonadmin policy and complete original-state screenshot comparison are the next integration checks.
