# My Computer and Control Panel icon rearrangement

The confirmed input defect was a missing namespace drag branch: the shared item handler created filesystem drags for C: folder contents and shortcut drags for Start Menu folders, but never created a rearrangement operation for My Computer drives or Control Panel applets. My Computer also bypassed the responsive namespace renderer, leaving view modes, clipping and scrolling inconsistent.

The patch adds a separate namespace-only drag lifecycle, without invoking file transfer, shortcut creation, drive opening or applet launch. It retains the initial pointer grab offset, includes scroll-coordinate changes, latches the drag threshold after crossing it, recomputes the final coordinate from the button-release endpoint, and cancels on Escape or release outside the client. Double-click navigation clears the drag. Successful moves persist using namespace kind + icon view + stable label, independent of item indices. Failed saves do not replace the stored position.

My Computer now uses the same clipped namespace renderer and exposes Large Icons, Small Icons, List, Details and Auto Arrange through View. Existing initial IE4 drive/Control Panel positions and their image/label offsets are retained in Large Icons. Manual placement is permitted in Large/Small with Auto Arrange off; List/Details remain ordered. A bounded original IE4 probe subsequently confirmed that My Computer has Auto Arrange unchecked. Root corrected the no-saved-setting default to False for My Computer, so C: can be moved immediately; an explicitly saved user choice remains authoritative. Control Panel retains the existing responsive Auto Arrange policy as an explicit discrepancy pending further native behavior work. The setting is saved separately for each namespace.

## Actual verification

- Six new pure geometry/persistence tests plus ten existing namespace layout tests: **16 passing**.
- `dev/check_namespace_rearrange.py` sends actual XTest motion/button/key events through X11/GTK at **800×600** and **1280×720** on isolated Xvfb displays, with temporary HOME and filesystem transfer patched to fail if called. Seven behavior groups pass at both sizes: actual pointer movement/release, threshold latch, Escape, outside-client cancellation, Auto Arrange policy, Small/List/Details behavior, stable keys after store reopen and bounded hit targets. Evidence: `private/screenshots/namespace-rearrange-800-run2-20261127/` and `private/screenshots/namespace-rearrange-1280-20261127/`.
- The existing **37-state** Control Panel layout regression passes, including narrow/wide layout, four view modes, last-item reveal, scrollbar drag, manual preservation/Auto Arrange reflow, resize/move and zero pixels outside the namespace client. Evidence: `private/screenshots/namespace-layout-rearrange-regression-20261127/`.

No live test VM was reset, deployed or manipulated. A leased, checkpoint-protected IE4 reference probe then established native behavior. `private/screenshots/namespace-native-20261127/arrange-menu.png` shows My Computer **View → Arrange Icons → Auto Arrange unchecked**. The actual native SysListView32 style is 1442841152 with `LVS_AUTOARRANGE` absent, captured in `private/reference-tools/namespace-drag-native-v3-20261127/drag.json`. A small Win32 USER `mouse_event` harness moved C: from pointer (354,194) to (401,277); `computer-select.png` and `drag-after.png` show the resulting free placement. This is real original-shell input, not a synthetic imitation of Windows controls.

The Control Panel ListView also has the auto-arrange style bit absent (1442840640), in `private/reference-tools/namespace-control-native-20261127/control.json`. That producer only queries its style: the inherited start/end JSON fields are not a claimed Control Panel drag. Its Web View View menu lacks the My Computer Arrange Icons group (`control-arrange.png`). Our responsive Control Panel Auto Arrange policy and currently flat menu access are therefore explicit unresolved differences. Native nested Arrange Icons placement is deferred to the next menu iteration; this patch provides discoverable functional View access now.

The temporary native floppy was ejected, the original VM restored to verified checkpoint `before-namespace-drag-20261127`, and its prior Keyboard/DateTime UI returned (`before.png`, `restored.png`). No new whole-window zero-difference comparison is claimed. The bounded reference establishes movement and observed profile defaults, not factory defaults for every release.
